# Political Philosophy Presentations

This folder is structured as a static GitHub Pages site.

## Publish it

1. Create a GitHub repository, such as `political-philosophy`.
2. Upload the site files and folders while preserving their structure.
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**.
5. Select the `main` branch and the `/ (root)` folder.

The live address will be:

```text
https://YOUR-USERNAME.github.io/political-philosophy/
```

The root `index.html` is the subject landing page. Choose **Political Philosophy** to open the existing course library; the library's presentation files remain in `Presentations/`, and the shared `presentation-polish.css` and `presentation-polish.js` files must stay beside those presentation HTML files. The Ethics page is ready for additional presentations.

## Editing

Edit a presentation HTML file locally or through GitHub, then commit the change. GitHub Pages will redeploy the updated version automatically.

Only upload files you want to make public. GitHub Pages sites are publicly accessible.

## Presentation authoring standards

Apply these rules to every new or revised deck in `Presentations/`:

- Do not create standalone quotation or epigraph slides. Put a short quotation on an explanatory slide or in the speaker notes, with the surrounding claim doing the teaching.
- Do not create standalone rhetorical-question or quasi-title transition slides. Move the transition into a concise section title or an explanatory content slide, then proceed directly to the argument.
- Design for classroom projection and distance reading. Use `Presentations/Justifying the State - Introduction and Social Contract.html` as the baseline for size and readability: let the main text use the available screen, avoid large unused whitespace, and scale headings, body copy, rows, and explanatory elements up until they are comfortably legible without clipping or overflow. This is a size and density reference only; do not copy its theme, colors, typography, or layout unless explicitly requested.
- Choose a visual theme that is materially different from the themes already used in the library. Inspect the existing decks before designing a new one; do not default to the green/light-green palette or reuse the same typography, background treatment, and decorative motif unless the user explicitly requests a template match.
- Keep section-title slides minimal and make the following content slide carry the explanation.
